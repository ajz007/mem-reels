# Phase 4 — credits, Razorpay entitlement, and My Reels

## Payment decision

Memory Reels uses Razorpay Standard Checkout for one-time INR credit packs. The browser receives only the public key ID and the server-created order fields. The key secret and webhook secret remain server-only.

Subscriptions are deliberately excluded.

## Credit ledger

The ledger is append-only. Entry types are `purchase`, `grant`, `reserve`, `consume`, `release`, and `administrative_adjustment`.

- A verified captured purchase adds credits once.
- Generation reserves the template recipe's credit cost only after compatibility validation and explicit proposal approval.
- Private delivery appends a consume record for the reservation.
- Provider or storage failure appends one compensating release.
- Existing ledger rows are never updated or deleted.

Purchase records move through `checkout_created`, `payment_pending`, `paid`, `failed`, `refunded`. A purchase receipt reference is generated by the server and does not contain a user name or email.

## Razorpay flow

1. The authenticated client selects a server-owned pack ID.
2. The server creates and stores a purchase intent and Razorpay order.
3. Standard Checkout opens with the public key and order ID.
4. `/api/provider-webhooks/razorpay` verifies `x-razorpay-signature` over the unmodified raw request body.
5. Only captured INR payments whose amount and order ID match the stored purchase grant credits.
6. `x-razorpay-event-id`, provider order ID, and provider payment ID are idempotency identities. Duplicate delivery does not grant twice.

The checkout success callback posts its payment ID, order ID and signature to `POST /api/verify-payment`. The server verifies HMAC-SHA256 against the order stored for the authenticated owner's purchase. Signature verification confirms authenticity but never grants credits; the verified captured-payment webhook remains the entitlement authority. Modal dismissal, payment failure and script-loading failure have explicit customer feedback.

## Public APIs

- `GET /api/account` — balance, server-owned packs, and owner purchase history.
- `POST /api/checkout-sessions` — creates a Razorpay order for a valid pack.
- `POST /api/provider-webhooks/razorpay` — signature-verified payment completion.
- `GET /api/reels` — owner-only reel library, including deletion state.

Private media continues to be delivered only through the authenticated owner route.

## Production persistence requirement

The repository ADR still has no selected production datastore. The JSON adapter remains local/test-only. Production checkout and payment grants always fail closed in this adapter. An environment flag cannot assert durability or bypass this guard; a transactional repository must be implemented before enabling production payments.

## Local setup and testing

Existing `.env` files are ignored by Git. Add newly generated **test** credentials locally as `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET`, and a separate `RAZORPAY_WEBHOOK_SECRET`. Never use `VITE_` for secrets. Rotate any credential shared in chat or committed accidentally. Restart `npm run dev` after changing environment values.

Open My Reels and select a credit pack to open Standard Checkout. Use Razorpay's official test payment details, not real payment details. A valid callback shows a pending confirmation message; credits arrive only through a signed captured webhook. For local webhook testing, a public HTTPS endpoint is required. Until that is configured, callback verification can succeed while the balance remains pending.

A production repository must atomically provide:

- unique Razorpay event, order, and payment IDs;
- a unique purchase-ledger grant;
- a single active reservation per generation attempt;
- exactly-one consume or release settlement per reservation;
- serializable balance checks and reservations for concurrent submissions;
- durable purchase, ledger, job, and deletion audit history;
- backup, reconciliation, retention, and administrative access controls.

Recommended environment names after that repository exists: `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, and `RAZORPAY_WEBHOOK_SECRET`.
